SOW §8.2: "At Project Closure, and again at the conclusion of the AMC period, the Vendor shall carry out a
complete handover to TMC … Handover shall be treated as complete only upon written acceptance by TMC IT,
following a demonstration that the delivered artefacts are sufficient to build, deploy, and operate the
solution independently of the Vendor."

**How to use.** For each item the Vendor fills in the evidence column; TMC IT verifies and initials.
Nothing in this checklist contains a credential: live credentials are handed over separately (Part C).

## Part B: Demonstration of independent build, deploy and operate

Performed by **TMC IT staff (or a TMC-nominated third party) at the keyboard**, with the Vendor only
observing, on a clean host provided by TMC. Each step uses only the handed-over artefacts.

| # | Step | Document | Pass criterion | Result | TMC IT |
|---|---|---|---|---|---|
| B1 | Clone the repository from TMC's own repository host | Installation Guide §3 step 1 | Clone succeeds without Vendor accounts | | |
| B2 | Create `.env` with fresh secrets (`scripts/make-env.sh`) and set the base domain | Installation Guide §3 step 2 | File created, mode 600 | | |
| B3 | Build and provision all six sites (`scripts/setup.sh`) | Installation Guide §3 step 3 | Ends with `setup complete` | | |
| B4 | Run the automated checks (`scripts/lint.sh`, `scripts/run-tests.sh`, `scripts/smoke-test.sh`) | Installation Guide §2, Test Plan | All pass | | |
| B5 | Restore the latest Production backup into this environment | Backup and Restoration §4 | Smoke test passes on restored data; audit-log integrity verified | | |
| B6 | Make a small code change, open a pull request, let CI run, merge and deploy to UAT | Installation Guide §4 | Pipeline green; change visible on UAT; `.release-history` updated | | |
| B7 | Roll back to the previous release | Installation Guide §5 | Previous release live; smoke test passes | | |
| B8 | Administer the CMS: create a user with a role on one unit site, publish through the review workflow, verify and export the audit log | CMS Administrator Manual | Actions recorded in the audit log | | |
| B9 | Rotate a secret (e.g. `DB_PASSWORD`) | System and Security Administration Manual §6 | Sites work with the new secret | | |
| B10 | Generate documentation outputs (`scripts/docs/build-docs.sh`) and the licence inventory (`scripts/licenses.sh`) | This checklist A10, A11 | Files produced | | |

## Part C: Credentials and access (handed over separately and securely)

Credentials are **never** written into this checklist, e-mail or chat. They are transferred in a sealed
envelope or through TMC's secret store in the presence of TMC IT, and each is **rotated by TMC** after
receipt.
