# OWASP Top 10 (2021): controls and evidence

How the TMC website ecosystem addresses each OWASP Top 10 (2021) risk, where the control lives in this
repository and what proves it works. Requirement IDs refer to [`docs/requirements/RTM.md`](../requirements/RTM.md)
(R-4.8-3, R-4.8-5, R-4.8-6, R-4.8-7, R-4.6-8).

Evidence is produced on every CI run of the merged code:

| Evidence | What it is | Where |
|---|---|---|
| `security-test.php` | WP-CLI test suite (about 125 checks) run against the TMH site | `scripts/tests/security-test.php` |
| `workflow-test.php` | Roles, review workflow, audit-log tamper detection | `scripts/tests/workflow-test.php` |
| Smoke checks | Live HTTP checks of headers, script nonces, security.txt, enumeration, admin allow-list | `scripts/smoke.d/security.sh` |
| Secret scan | gitleaks over the whole git history | `.github/workflows/security.yml`, job `secrets` |
| Image scan | Trivy over the built `tmc-wordpress` image, plus Dockerfile/compose configuration scan | `.github/workflows/security.yml`, job `image` |
| DAST baseline | OWASP ZAP baseline scan of a freshly provisioned stack | `.github/workflows/security.yml`, job `dast` |

The CI artifacts `security-secrets-report`, `security-image-reports` and `security-dast-reports` hold the
reports for each run (kept 30 days). Attach the reports of the release candidate to the pre-VAPT pack
([`pre-vapt-checklist.md`](pre-vapt-checklist.md)).

## A01 Broken Access Control

| Control | Implementation | Evidence |
|---|---|---|
| Role-based access: Super Admin, Site Administrator, Reviewer / Publisher, Content Editor | `src/mu-plugins/tmc-core/roles.php`, WordPress capabilities | `workflow-test.php` (Content Editor cannot publish, unit isolation) |
| Review before publication | `src/mu-plugins/tmc-core/workflow.php` | `workflow-test.php` |
| Administration reachable only from allow-listed networks (`TMC_ADMIN_ALLOW_CIDRS`; default RFC 1918, 100.64.0.0/10, loopback). `wp-login.php` and `/wp-admin/` answer 403 to other addresses; anonymous `admin-ajax.php` / `admin-post.php` stay public | `security-network.php` | `security-test.php` section 1; smoke: 403 for `wp-login.php` and `/wp-admin/` from 198.51.100.7 |
| Privileged accounts without two-factor authentication can open only their profile until they enrol; REST calls refused | `security-mfa.php` (`tmc_account_gate*`) | `security-test.php` section 4 |
| No code changes from the admin screens: theme/plugin editor off everywhere (`DISALLOW_FILE_EDIT`); installs and updates off on the server (`DISALLOW_FILE_MODS`, `file_mod_allowed`) | `docker-compose.yml`, `security-session.php` | `security-test.php` section 8 |
| Application passwords (API credentials) off, except for roles listed in `TMC_APP_PASSWORD_ROLES` | `security-session.php` | `security-test.php` section 5 |
| XML-RPC blocked at Apache and in WordPress | `wordpress/apache-tmc.conf`, `security-headers.php` | smoke: `/xmlrpc.php` 403 |

## A02 Cryptographic Failures

| Control | Implementation | Evidence |
|---|---|---|
| HTTPS with HSTS (one year; `includeSubDomains` only when `TMC_HSTS_INCLUDE_SUBDOMAINS=1`) whenever the request is HTTPS; `upgrade-insecure-requests` in the CSP | `security-headers.php`; TLS terminates at the reverse proxy (operations) | `security-test.php` section 8 |
| Passwords hashed by WordPress core (bcrypt since WordPress 6.8) | WordPress core | — |
| Audit entries chained with HMAC-SHA256; key only in the environment | `audit-log.php` | `workflow-test.php` tamper check |
| Secrets only in `.env` (mode 600, generated by `scripts/make-env.sh`, never committed) | `scripts/make-env.sh`, `.gitignore` | CI secret scan |
| No patient or clinical data is stored in the CMS | Policy (`docs/engineering/CONVENTIONS.md`) | — |

Residual risk: the Two Factor plugin stores each user's TOTP seed in the database. The database is on an
internal Docker network with no host ports and no internet access, and database credentials exist only in
the environment.

## Configuration reference

All settings are environment variables passed to the containers by `docker-compose.yml` (`x-wp-env`). Unset
means the secure default. Variables marked * are read by the code but not yet passed through
`docker-compose.yml`; add them to `x-wp-env` to change the default.

| Variable | Default | Effect |
|---|---|---|
| `TMC_ENFORCE_MFA` | `1` | `0` disables MFA enforcement. Only for automated test environments that must sign in to the admin screens without an authenticator; never on UAT or production. |
| `TMC_MFA_GRACE_HOURS` | `0` | Hours a newly privileged account may work before it must enrol. |
| `TMC_ADMIN_ALLOW_CIDRS` | private ranges | Comma-separated IPv4/IPv6 ranges allowed to use `wp-login.php` and `/wp-admin/`. Replaces the default. For VAPT, add the testing agency's addresses for the test window. |
| `TMC_ADMIN_IDLE_MINUTES` | `30` | Idle timeout for signed-in sessions (`0` = off). |
| `TMC_APP_PASSWORD_ROLES` | empty | Roles allowed to create application passwords (e.g. an integration role). |
| `TMC_SECURITY_CONTACT` | placeholder | `mailto:` or `https:` contact(s) for `security.txt`. **To be confirmed by TMC before go-live.** |
| `TMC_HSTS_INCLUDE_SUBDOMAINS` | `0` | Add `includeSubDomains` to HSTS once every host under the domain serves HTTPS. |
| `TMC_ENV` | `local` | `server` disables plugin/theme/core installs and updates from the admin screens. |
| `TMC_DISALLOW_FILE_MODS`* | — | `1`/`0` overrides the `TMC_ENV` rule above. |
| `TMC_LOGIN_MAX_ATTEMPTS`*, `TMC_LOGIN_MAX_ATTEMPTS_IP`*, `TMC_LOGIN_WINDOW`*, `TMC_LOGIN_LOCKOUT_BASE`*, `TMC_LOGIN_LOCKOUT_MAX`* | 5, 20, 900 s, 60 s, 3600 s | Login throttling. |
| `TMC_ADMIN_SESSION_HOURS`* | `12` | Longest session for privileged accounts. |
| `TMC_PASSWORD_MIN_LENGTH`* | `12` | Minimum password length for privileged accounts. |
| `TMC_HSTS_MAX_AGE`* | 31536000 | HSTS max-age in seconds. |
| `TMC_SECURITY_TXT_EXPIRES`* | today + 180 days | Fixed `Expires:` for `security.txt` (`YYYY-MM-DDTHH:MM:SSZ`). |

Extending the CSP (for example a map tile server or an approved video host): add the origin through the
`tmc_csp_directives` filter in the module that needs it, never by loosening the whole policy. The analytics
origin (when `analytics.php` is configured for Matomo or GA4) is added automatically.

Note for full-page caching: the CSP nonce changes on every request, so a page cache must store and replay the
`Content-Security-Policy` header together with the page, or bypass cached pages.

## Accepted DAST findings

The ZAP baseline treats the rules below as accepted (reported as WARN or ignored). The authoritative list,
with the same justifications, is [`security/zap-baseline.conf`](../../security/zap-baseline.conf).

| Rule | Finding | Justification |
|---|---|---|
| 10055 | CSP: `style-src 'unsafe-inline'`; login/admin baseline policy | WordPress core block supports print inline `style` attributes; styles cannot execute script. Public-page scripts are nonce-only. Core login/admin screens still print inline scripts and use underscore templates (eval), so they get a baseline policy; they are reachable only from the admin allow-list. |
| 10010, 90033 | `pll_language` cookie without HttpOnly, scoped to the network domain | Holds only the visitor's language choice so it follows the visitor across TMC sites; read by the language switcher; no personal or session data. |
| 10011 | Cookie without Secure flag | CI scans over plain HTTP; on HTTPS WordPress and Polylang set `Secure`. |
| 10054 | Cookie without SameSite | Reviewed per cookie; authentication cookies are path-scoped and all state changes need a WordPress nonce. |
| 10202 | Absence of anti-CSRF tokens | The public search form is a GET form without side effects; state-changing forms use nonces. |
| 90004 | Insufficient site isolation (Spectre) | COOP and CORP are set; COEP `require-corp` would block shared network assets without protecting any secret on public pages. |
| 10027, 10110 | Suspicious comments / dangerous JS functions | Pattern matches in minified WordPress core libraries; project JavaScript uses neither `eval` nor untrusted `innerHTML`. |
| 10108 | Reverse tabnabbing | External links opened in a new tab carry `rel="noopener noreferrer"` (theme). |
| 10015, 10049, 10050, 10096, 10109, 10111, 10112, 10113, 10116 | Informational | Cacheable public content, asset version timestamps, pinned scanner version. |

Trivy exceptions: none (`security/trivyignore` sets the rules for adding one). gitleaks exceptions: only the
deliberately weak example passwords used by the password-policy tests (`security/gitleaks.toml`).
